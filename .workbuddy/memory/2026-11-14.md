## 0.3.6 上架后修复：删空棚号行不回收 + 超上限提示位置（00:20-）

### 背景与定版
- 0.3.6 已上架（`dist\mixcalc-0.3.6-release-signed.app`，SHA256 `06FCF1E5…343A`，保持不动）。
- 用户指出同版本号不能再发，**本次升 `0.3.7 / versionCode 1000307`**（`AppScope/app.json5`）。

### 根因
- 结算模型 `RowSettlement.recycleDeadRows` 本来就支持 `emptiedByUser`：有内容或「本次被删空」的行整行回收。
- 鸿蒙只有两条路径传了它：删除号码气泡、转入；四条「离开编辑」路径都传空数组：
  `finishEdit`（失焦）、`nextRowDown`（下一行）、`nextCell`（下一步/回车）、`openEditor`（换格）。
- 填过料的行靠 `hasContent` 回收，所以表现为「时好时坏」；只有「光有棚号没填料」的行会漏。
- 安卓统一在 `CellEditorOverlay.begin/end → onCellEditEnd` 用 `shedEditSnapshot` 对比当前值，所有出口都覆盖。

### 修复
- 模型新增纯函数 `isEmptyingShedEdit(beforeText, row)`：编辑前非空 && 现在棚号 trim 为空 && `shedCount <= 0`。
- `MixCalcTable` 新增 `shedTextBeforeEdit(row)` / `emptiedByTyping(before, row)`；
  四个出口都必须在 `endShedEdit()` / `applyEdit(..., true)` **之前**抓 `shedEditSnapshot`，否则快照已被清空。
- `openEditor` 的提前 `endShedEdit()` 不能删（防脏快照），所以判定放在它之前、结算时再算。
- 顺序提示（`firstEmptyRow`）仍优先于结算，两端一致：下面全空时先提示，不回收。

### 超上限提示

### 外部复核（小艺/DeepSeek）评估：openCustomDialog 路线
- 对方事实成立：`ShowToastOptions` 无 height/cornerRadius/fontSize（本机 SDK 独立核过一致）；`BaseDialogOptions` 确有 width/height/cornerRadius。
- 但推荐 `openCustomDialog` 做胶囊提示，**对本项目不适用**：① 位置又要靠 alignment+offset 猜标题栏高度（同 11-14 废掉的 dy 72）；② `warnOverLimit()` 由 `applyEdit()` 触发，正在 TextInput 编辑中，弹窗抢焦点会打断 `onBlur` 结算链路、收键盘（`isModal:false`+`focusable:false` 仅 API 19 起）；③ 生命周期从 1 个布尔变成 Promise<number> id + 竞态。
- 结论：仍走页面内 `Row` + 胶囊 `Text`（外层几何/穿透/层级不动，内层去 100% 宽 + `borderRadius(hh()/2)`）。评估已写入 `docs/超上限横幅改胶囊-复核说明.md` §8。
